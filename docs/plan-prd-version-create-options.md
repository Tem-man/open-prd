# 版本新建选项调整 — 实施规划

> 需求来源：用户对话（2026-09-30）
> 状态：**✅ 已实施**（2026-09-30；同日改为顶部只建空白、行内 copy 复制被点的版本行）
> 前置：[`plan-prd-version-management.md`](./plan-prd-version-management.md) 已落地（Figma Page 模型、手动建版本、对话随版本走）
> 关系：本方案调整「新增版本」的四种组合，并**移除行内克隆**；不改切换 / 删除 / 懒引导 / 写回工作区模型。

---

## 一、要解决什么

当前「新增版本」只有两档，行内另有「克隆」：

| 入口                   | PRD          | 对话                             |
| ---------------------- | ------------ | -------------------------------- |
| 新增 → 复制当前内容    | 复制工作区   | **整段对话都复制**               |
| 新增 → 空白版本        | 清空         | **对话清空**                     |
| 行内克隆（任意版本行） | 复制该行 PRD | **对话清空**（信息收集一并丢掉） |

用户要的是另一套划分：

1. **去掉克隆版本**（行内按钮、确认框、`POST .../clone`、`clonePrdVersion`）。
2. **复制版本**拆成两种组合：复制 + 会话记录；复制 + 不带会话记录。
3. **空白版本**拆成两种组合：空白 + 两轮信息收集；空白 + 不带两轮信息收集。
4. 复制的两种组合都要**留下两轮信息收集得到的信息**。
5. 「空白 + 两轮信息收集」**仅当历史上确实走过提问表单**才可选。首条需求已经足够、Agent 直接 `generate_prd`、从未出现信息收集问答时，这条组合不出现 / 不可用。

克隆原先承担的「只要文档、不要后期编辑闲聊」由 **复制 + 不带会话记录** 替代；区别是新组合仍保留信息收集，且只作用于**当前工作区**（要基于历史版本，先点进该版本再新增）。

---

## 二、两个概念

对话时间线按生成边界切成两段，不要把「会话记录」和「信息收集」当成同一份数据。

```
[信息收集前缀]                          [会话记录 = 生成后的编辑对话]
用户首条需求
  →（可选）第 1 轮 ask_user_form + 用户作答
  →（可选）第 2 轮 ask_user_form + 用户作答
  → 首次 generate_prd 的助手说明
────────────────────────────────────────►
之后的改写、确认卡片、chip 编辑、闲聊……
```

| 名词                       | 指什么                                                                                                                           | 落在哪                                         |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| **信息收集前缀（intake）** | 从会话开头到**首次生成 PRD** 为止的消息。含用户原始需求、至多两轮 `ask_user_form` 及对应作答；复制场景还含首次生成那条助手说明。 | `messages` / 版本行 `messages_json` 的前缀切片 |
| **会话记录**               | 首次 PRD 生成**之后**的消息（对话式编辑、整份重生成确认、后续提问等）。                                                          | 同上，前缀之后的尾巴                           |
| **两轮信息收集问答**       | 前缀里至少出现过一次**收集表单**（`ask_user_form`，不是整份重生成确认卡）。                                                      | 用表单形态判定，见 §3                          |

`loadHistory` 仍会把前缀里的用户原文和表单作答喂给模型。复制时丢掉会话记录、留下前缀，新版本上的 Agent 仍然知道当初收集到的需求；空白版本带前缀时，工作区没有 PRD，收集阶段提示词生效，用户再说「生成」即可 `generate_prd`，不必重填两轮表单。

## 三、如何切前缀（实现约定）

不新增表、不加消息 `kind`。用现有落库形态切：助手 `content` 里的 `[QUESTION_FORM]…[/QUESTION_FORM]`（见 `withFormBlock` / `extractQuestionForm`）。

| 形态                                      | 判定                                    | 是否算信息收集       |
| ----------------------------------------- | --------------------------------------- | -------------------- |
| 收集表单                                  | 解析后有 `questions`，**没有** `action` | 是                   |
| 整份重生成确认卡                          | 解析后有 `action`（pending token）      | 否，已进入生成后流程 |
| `meta.kind === "prd_edit"` / `meta.edits` | 模块改写记录                            | 否                   |

**从时间线开头顺序扫描：**

1. 用户消息 → 一律收入前缀（含首条需求、表单作答）。
2. 助手且为**收集表单** → 收入前缀，并记 `hasCollectionForm = true`。
3. 助手且为确认卡，或带编辑 `meta` → **在此停**（本条不进前缀）。
4. 其它助手消息（无收集表单）→ 视为**首次生成说明**（或收集阶段一句过渡）：
   - **复制**：收入前缀后停止（PRD 还在，历史需与「已经生成过」一致）。
   - **空白**：本条不收，然后停止（工作区无 PRD，不能让历史看起来已经生成完）。

`hasCollectionForm === true` 时，才认为「有两轮信息收集问答」。没有收集表单时（首条就够用、直接生成），`hasCollectionForm === false`，「空白 + 两轮信息收集」禁用。

边界：

- 只走了一轮表单也算「有信息收集」，选项仍可用（产品文案仍叫「两轮」，实现按「出现过收集表单」而不是硬数 2）。
- 生成**之后**的 `ask_user_form`（定位歧义、全局变更二选一）落在会话记录里，**不**算信息收集前缀。
- 中断标记助手消息若出现在首次生成之前，跟其它收集阶段助手一样处理。

抽成后端纯函数，例如 `splitIntakeMessages(messages, { includeFirstGenerate })`，供建版本与单测共用。

## 四、四种组合

「新增版本」仍只针对**当前工作区**（先 `writeBackActiveVersion`）。`source` 只保留 `snapshot` / `blank`，不为四种组合加新枚举。已有 `source='clone'` 行实施时一次性改写成 `snapshot`，类型与 UI 不再出现 clone。

| #   | 组合                    | `mode`      | 消息策略                             | PRD / 工作区                                   | `source`   |
| --- | ----------------------- | ----------- | ------------------------------------ | ---------------------------------------------- | ---------- |
| A   | 复制 + 会话记录         | `duplicate` | 工作区**全部**消息                   | PRD 与模块不变，工作区不重建（与今天复制相同） | `snapshot` |
| B   | 复制 + 不带会话记录     | `duplicate` | **仅信息收集前缀**（含首次生成说明） | PRD 与模块不变；**只替换** `messages`          | `snapshot` |
| C   | 空白 + 两轮信息收集     | `blank`     | 仅前缀，**不含**首次生成说明         | 清空 HTML / 模块 / outline（与今天空白相同）   | `blank`    |
| D   | 空白 + 不带两轮信息收集 | `blank`     | `[]`                                 | 同今天空白                                     | `blank`    |

约束：

- A / B **一律保留信息收集前缀**。B 只丢掉生成后的会话记录；没有收集表单时，前缀至少是「首条用户需求 + 首次生成说明」。
- C 仅当 `hasCollectionForm` 为 true；否则前端禁用，后端返回 400。
- D 不依赖是否做过收集。
- 内部调用 `createPrdVersion({ mode: "duplicate" })`（整份重生成「先另存再生成」，`messages.ts` 的 `save_version_then_regenerate`）**默认 A**（完整对话），行为与现在一致。

空白路径继续：`preserveUnversionedWorkspace` → 写回旧激活版本 → 空 `sections_json` / 空 HTML → `loadVersionIntoWorkspace`（C 时 `messages_json` 为前缀而非 `[]`）。复制路径：A 不碰工作区消息；B 在插入版本行后对工作区执行 `writeMessagesIntoWorkspace(前缀)`。

## 五、API

### 5.1 扩展创建接口

`POST /api/sessions/:id/prd/versions`

```ts
{
  label?: string
  mode: "duplicate" | "blank"
  /** 复制：是否带上生成后的会话记录。默认 true（= 组合 A） */
  copyConversation?: boolean
  /** 空白：是否带上信息收集前缀。默认 false（= 组合 D）。复制时忽略，服务端视为始终保留前缀 */
  copyIntake?: boolean
}
```

| body                                                | 组合 | 校验                                     |
| --------------------------------------------------- | ---- | ---------------------------------------- |
| `{ mode: "duplicate" }` 或 `copyConversation: true` | A    | 无                                       |
| `{ mode: "duplicate", copyConversation: false }`    | B    | 无                                       |
| `{ mode: "blank", copyIntake: true }`               | C    | 当前工作区 `hasCollectionForm`，否则 400 |
| `{ mode: "blank" }` 或 `copyIntake: false`          | D    | 无                                       |

响应形状不变：`{ id, version, assembledPrdHtml }`。B 之后前端仍走现有 `refreshWorkspace`（会 `fetchSession` 重拉消息）。

### 5.2 删除克隆

- 删除 `POST /api/sessions/:id/prd/versions/:vid/clone`。
- 删除 `clonePrdVersion`。
- `source` 类型去掉 `"clone"`；库里已有 clone 行改写成 `snapshot`。

### 5.3 前端如何知道 C 是否可点

打开「新增版本」时，当前会话消息已在 `messages` store。前端用与后端相同的规则扫一遍即可（抽共享判定，或前端只认「助手 content 含 `[QUESTION_FORM]` 且 JSON 无 `action`」）。不另开 GET。后端在 `copyIntake: true` 时再校验一次，防止绕过 UI。

## 六、前端

### 6.1 去掉克隆

`VersionDrawer.vue`：行内「克隆为新版本」按钮、确认弹窗、`cloneTarget`。`prdVersions` store：`cloneVersion`。

基于某份历史 PRD「只要文档、不要后期闲聊」：先点该版本打开，再「新增版本 → 复制当前内容 → 不带会话记录」。

### 6.2 「新增版本」弹窗

保留名称输入。主选项仍是两个 radio：**复制当前内容** / **空白版本**（默认仍是空白，与今天一致）。

选中某一主选项后，出现对应的二级组合（勿一次平铺四个主按钮，避免和「方式」抢层级）：

**复制当前内容**

- 带会话记录（默认）— 平行版本，编辑对话一并带走。
- 不带会话记录 — 只要文档和信息收集，生成之后的对话不要。

**空白版本**

- 不带两轮信息收集（默认）— 空文档、空对话，新开一轮收集（若新输入仍不够）。
- 带两轮信息收集 — 空文档，对话里只留下当时的提问与作答，可直接再生成。  
  `hasCollectionForm === false` 时禁用，附一句说明：当前会话没有信息收集问答（需求一开始就够用）。

文案可按 UI 微调，语义以 §4 为准。

### 6.3 列表徽章

继续用 `source`：`snapshot` → 快照，`blank` → 空白。四种组合不新做徽章；不再有「克隆」徽章。

## 七、非目标

- 不改激活 / 删除 / 懒引导 / 未版本化保护存档。
- 不为 intake 新建列或表；`source` 合法值仅 `snapshot` / `blank`。
- 不改收集阶段 Prompt、两轮提问规则、`ask_user_form` / `generate_prd`。
- 不让「新增版本」作用于非激活版本行（克隆能做到的「先切过去」由用户手动切换取代）。
- 不做版本列表上的「从该行复制」快捷入口（需要的话以后再加）。
