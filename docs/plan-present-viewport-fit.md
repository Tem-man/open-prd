# 放映视口适配改造计划（长页不再被整帧缩小）

> 背景：PC 长页画板（如 `DongtingHome`）进入 `/prototype/:id/present` 后被缩成中间细条、左右大片灰底。  
> 根因：当前 `PresentView` 使用 **整帧 contain**（宽高同时塞进窗口），长页高度先触顶，等比缩小把宽度一并压掉。  
> 目标：放映体验接近「真浏览器打开网页」——宽度尽量铺满可用区域，高度超出时可滚动查看。

---

## 一、现状与问题

### 1.1 当前算法（`PresentView.vue`）

```ts
scale = min(1, 可用宽 / 画板宽, 可用高 / 画板高);
```

| 约束                               | 行为                         |
| ---------------------------------- | ---------------------------- |
| `scale ≤ 1`                        | 只缩小不放大                 |
| 宽、高同时参与                     | 谁先顶边谁决定最终缩放       |
| `root` 为 `overflow-hidden` + 居中 | 超出部分不可滚，整帧必须可见 |

### 1.2 为何 PC 长页特别惨

长页画板典型比例：宽 ~1440、高数千～上万。窗口高度远小于画板高度 → **高度成为瓶颈** → scale 很小 → 宽度也跟着缩小 → 左右留白。

手机画板（如 390×844）在多数显示器上整帧 contain 仍接近可用宽度，问题不明显，所以此前未暴露。

### 1.3 相关文件

| 文件                                                            | 角色                                            |
| --------------------------------------------------------------- | ----------------------------------------------- |
| `frontend/src/pencil/PresentView.vue`                           | 缩放计算、舞台尺寸、根布局                      |
| `frontend/src/pencil/theme/prototype.ts`                        | `root` / `stage` 样式（含 `overflow-hidden`）   |
| `frontend/src/pencil/components/prototype/PrototypeFrame.vue`   | 按 `width*scale` × `height*scale` 画完整 canvas |
| `frontend/src/pencil/components/prototype/PrototypeOverlay.vue` | Overlay 定位，依赖同一 `scale`                  |
| `frontend/src/pencil/components/prototype/PrototypeToolbar.vue` | 顶栏（暂无缩放模式切换）                        |

引擎侧 `packages/core/src/prototype/*`（跳转、转场、命中）**不必改**；命中坐标已按 frame-local 换算，与 CSS 滚动兼容。

## 二、目标体验

| 场景                               | 期望                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| PC 长页（高 ≫ 视口高）             | 按**宽度**适配；整页可**纵向滚动**；左右不再因高度而缩成细条 |
| 手机 / 短画板（缩放后高度 ≤ 视口） | 居中展示，行为与现在接近（可仍略有边距）                     |
| 超宽画板（宽 > 可用宽）            | 仍按宽度缩小到可用宽；高度随之等比                           |
| 画板小于视口                       | 保持 `scale ≤ 1`，居中，不强制拉满（避免糊）                 |
| 转场 / Overlay / 点击热区          | 继续可用；滚动后点击坐标正确                                 |
| 直接打开放映 URL / 无 store        | 现有重定向逻辑不变                                           |

非目标（本次不做）：

- 放映内自由捏合缩放、百分比缩放条（可列为后续增强）
- 改画板设计稿本身的尺寸或响应式断点
- 改编辑器画布的 zoom/pan

## 三、方案选型

| 方案                                     | 做法                                              | 结论                                                                        |
| ---------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------- |
| A. 仅改默认：Fit Width + 纵向滚动        | `scale = min(1, 可用宽/画板宽)`；根容器可纵向滚动 | ✅ **采用为默认**。改动面小，直接对齐「真网页」预期                         |
| B. 智能自动                              | 长页用 Fit Width；短页 / 接近视口比例用 Contain   | ✅ **建议一并做**。避免矮画板在超宽屏上被拉得过宽后上下贴边难看；规则见 3.1 |
| C. 工具条切换 Fit / Fit Width / 实际大小 | 对齐 Figma Present 的缩放菜单                     | ⏳ **P1 可选**。默认策略正确后，再加手动切换                                |
| D. 只渲染视口切片、画板内虚拟滚动        | 大 canvas 性能优化                                | ❌ 本次不做。先接受整帧 canvas + CSS 滚动；超高画板性能问题另开优化         |

### 3.1 默认缩放策略（推荐）

```text
fitWidthScale = min(1, availableWidth / frame.width)
scaledHeight  = frame.height * fitWidthScale

若 scaledHeight <= availableHeight:
  → 使用 fitWidthScale，舞台在视口内垂直居中（短页 / 手机）
否则:
  → 仍使用 fitWidthScale，根容器 overflow-y: auto，从顶部开始展示（长页）
```

说明：

- **不再把 `availableHeight / frame.height` 乘进默认 scale**，这是修掉「细条」的关键。
- `STAGE_MARGIN`（现 48）保留用于左右边距；长页模式下上下边距可改为仅底部留白或滚动到底再留一点，避免首屏被边距吃掉过多。
- `scale` 仍封顶为 `1`（不放大），与上游一致。

### 3.2 布局结构调整

当前：`root` = `fixed inset-0 flex items-center justify-center overflow-hidden`

改为：

| 模式                        | root                                            | stage 位置               |
| --------------------------- | ----------------------------------------------- | ------------------------ |
| 短页（缩放后高度 ≤ 可用高） | `flex` 居中 + `overflow-hidden`                 | 水平+垂直居中            |
| 长页（缩放后高度 > 可用高） | `overflow-y-auto overflow-x-hidden`，内容顶对齐 | 水平居中，垂直从顶部开始 |

实现上可用一个 `needsScroll` 计算属性驱动 class，避免两套模板。

## 四、风险与注意点

| 风险             | 说明                                                                               | 处置                                                               |
| ---------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 整帧 canvas 过高 | 万像素级高度 × devicePixelRatio，内存与首次绘制变重                                | 先落地体验；若卡顿，后续再做视口裁剪渲染（方案 D）                 |
| 滚轮与热区       | 滚动条区域 / 页面滚动时，`toLocal` 仍基于 canvas `getBoundingClientRect`，一般正确 | 验收时重点测：滚到中下部再点热区                                   |
| Overlay          | Overlay 相对 stage 定位；stage 随页面滚动时 Overlay 应跟着走                       | 保持 Overlay 仍是 stage 的子节点即可                               |
| 转场             | `getFrameTransitionStyle` 用的是舞台像素尺寸；换帧时若高度差大，滚动位置需重置     | 切换 `currentFrameId` 时把 root `scrollTop = 0`                    |
| 工具条遮挡       | 固定右上角，长页滚动时仍浮在视口上                                                 | 保持现状；内容勿依赖被工具条盖住的热区，或后续给工具条留 safe area |
| 主题样式         | `theme/prototype.ts` 的 `overflow-hidden` 与长页滚动冲突                           | 长页 class 覆盖或把 overflow 从 theme 挪到 PresentView 按模式绑定  |

## 五、实施步骤

### Step 1 — 默认 Fit Width + 条件滚动（必做）

1. 改 `PresentView.vue` 的 `scale` 计算：去掉高度项，仅 `min(1, availableWidth / frame.width)`。
2. 增加 `needsScroll`（或 `isTallFrame`）：`frame.height * scale > availableHeight`。
3. 按 `needsScroll` 切换 root 的 overflow / 对齐方式（见 3.2）。
4. 切帧时重置滚动位置。
5. 微调 `STAGE_MARGIN`：长页模式可只用左右 margin，或减小上下 margin，让首屏更接近浏览器。

**交付判定：**

- [ ] 打开 `DongtingHome` 类长页：宽度接近窗口可用宽，左右无大块无意义灰边（仅边距）。
- [ ] 可纵向滚动看完整页。
- [ ] 手机短画板仍大致居中，不被拉成怪异比例。
- [ ] 点击跳转、返回、Esc 退出仍正常。
- [ ] 滚到页面中下部再点热区，跳转仍正确。

### Step 2 — Overlay / 转场回归（必做，与 Step 1 同 PR）

1. 有 Overlay 的原型：打开 Overlay 后滚动、点 backdrop 关闭。
2. 带转场的帧切换：动画方向与距离仍合理；切帧后回到顶部。

### Step 3 — 工具条缩放模式（可选，P1）

在 `PrototypeToolbar` 增加简单切换：

| 模式             | 行为                                   |
| ---------------- | -------------------------------------- |
| 适应宽度（默认） | Step 1 策略                            |
| 适应屏幕         | 恢复当前 contain（整帧可见、可能缩小） |
| 实际大小         | `scale = 1`，宽高均可滚                |

状态可用模块级 `shallowRef` 或 `sessionStorage`，刷新可记住。文案用简体中文。
