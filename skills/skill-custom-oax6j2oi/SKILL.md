# 商业画布

以商业画布形式展示应用的商业价值，围绕目标客户、价值主张、渠道通路、客户关系、收入来源与成本结构六个模块展开，全部以 `<table class="prd-table">` 表格结构呈现，可直接渲染。

## 工作流程

1. **确认应用基本信息**：获取应用名称、产品类型（App / Web / SaaS / 小程序等）、所处阶段（概念期 / 增长期 / 成熟期）、所属行业。信息缺失时向用户提问，不要自行编造为既定事实。

2. **逐模块收集与推断内容**：按固定顺序梳理六个模块：
   - 目标客户与细分市场
   - 核心价值主张
   - 渠道通路与客户触达
   - 客户关系与留存策略
   - 收入来源与盈利模式
   - 关键资源与成本结构

3. **交叉校验模块一致性**：
   - 价值主张是否对应目标客户的真实痛点
   - 渠道通路是否能触达已定义的目标客户
   - 客户关系策略是否能支撑留存目标
   - 收入来源是否由关键资源与成本结构支撑，毛利逻辑是否成立

4. **标注假设**：凡属推断而非用户明确提供的信息，在「依据与假设」列注明「假设」；用户提供或行业公开数据注明「依据」。

5. **量化收入与成本**：收入来源给出计价方式与占比区间（合计 100%）；成本结构给出构成项与占比区间（合计 100%）。

6. **按输出规范生成表格**，并执行「生成规则（必须遵守）」中的自检清单。

## 输出规范

- **展示形式**：全部内容使用 `<table class="prd-table">` 结构，包含 `<thead>`、`<tbody>`、`<th>`、`<td>`。不使用 Mermaid 图、思维导图或纯文段罗列。
- **表格组成**（按顺序输出）：
  1. 商业画布总览表
  2. 目标客户与细分市场明细表
  3. 核心价值主张明细表
  4. 渠道通路与客户触达明细表
  5. 客户关系与留存策略明细表
  6. 收入来源与盈利模式明细表
  7. 关键资源与成本结构明细表
- **总览表表头**：`画布模块` | `核心内容` | `商业价值指向`
- **明细表表头**：`要素` | `具体内容` | `依据与假设`
- **收入/成本表表头**：`项目` | `说明` | `占比区间`
- **引导语**：每张表格前可加一句 `<p>` 引导语，不超过 40 字；实质性内容必须放在表格内，不得只在文段中表达。
- **格式约束**：不使用内联样式、`<script>`、外部资源引用；单元格内如需列举，用「、」或「；」分隔，不嵌套列表标签。
- **术语统一**：统一使用「客户」指代付费方或使用者；统一使用「画布模块」指代六个板块；统一使用「占比区间」表示百分比区间。
- **篇幅**：总览表 6 行；各明细表 3–5 行；收入表与成本表各 3–5 行。

## 生成规则（必须遵守）

1. 所有内容必须紧扣「商业画布」主题，不得偏离到产品功能清单、技术架构、竞品分析等其他主题。
2. 必须覆盖六个画布模块，顺序固定为：目标客户与细分市场 → 核心价值主张 → 渠道通路与客户触达 → 客户关系与留存策略 → 收入来源与盈利模式 → 关键资源与成本结构，不得增删或调换。
3. 全部内容以 `<table class="prd-table">` 表格呈现，表格必须包含 `<thead>`、`<tbody>`，表头使用 `<th>`，数据行使用 `<td>`；不得使用 Mermaid 图、思维导图、`<script>` 或纯文段替代表格。
4. 表格前如加引导语，必须使用 `<p>` 标签且不超过 40 字；不得将实质内容只写在文段中。
5. 不使用内联样式、`class` 之外的属性、外部资源引用与脚本标签。
6. 收入来源表与成本结构表必须给出占比区间，且各表占比区间合计可覆盖 100%。
7. 明细表中每一条内容必须标注「依据」或「假设」，不得留空；推断信息一律标注「假设」。
8. 术语统一：统一使用「客户」「画布模块」「占比区间」，不得混用多种表述。
9. 不得出现时效性信息（如具体年份、当前股价、近期某事件），不得编造具体企业真实数据。
10. 输出前自检：六模块是否齐全、表格语法是否闭合完整、占比是否合理、是否可直接渲染。
