# 2026-11-14

## Windows exe 打包计划（仅文档，未改代码）

- 交付：`docs/plan-windows-exe-packaging.md`。
- 调研结论：`electron/` 骨架（electron-vite 5 / Electron 42.1.0 / electron-builder 26.8.1）与后端 userData 路径注入已就绪，但现有 `win.loadFile()` 的 `file://` 方案不可行。
- 五个硬阻塞：① 前端 40+ 处 `fetch("/api/...")` 在 file:// 下全废；② `createWebHistory` 深链失效；③ `electron/package.json` 无 dependencies，`import("backend")` 打包后解析不到；④ better-sqlite3 需按 Electron ABI 重编译且不能进 asar；⑤ `win.loadFile` 路径算错（实际产物在 `process.resourcesPath/frontend/dist`）。
- **技术选型（后续实施按此走）**：主进程内 Express 同源 HTTP 托管（`http://127.0.0.1:<随机端口>`，静态托管 frontend/dist + SPA fallback），`BrowserWindow.loadURL` 取代 loadFile；前端业务代码零改动。配套给 `frontend/vite.config.ts` 加 `ELECTRON_BUILD=1 → base: "/"` 开关（Web 保持 `./`），解决深链刷新时 `./assets` 解析错误 —— 这也意味着 AGENTS.md 里「base 不能改回 /」的约束只对 file:// 成立。
- 后端依赖用 `pnpm --filter backend deploy --prod .packaging/backend` 生成自包含目录作为 extraResources（`to: backend/`），主进程用 `pathToFileURL` 绝对路径动态 import；该布局与 `skillDirs.ts` 的 BUILTIN_SKILLS_ROOT 上溯三级路径天然吻合，无需改后端路径代码。
- 其余：`backend/src/index.ts` 的 `isMain`（`process.argv[1].endsWith("index.js")`）需加 `OPENPRD_EMBEDDED` 守卫防二次启动；`startServer(0)` 随机端口 + 回环绑定；产物 NSIS 安装版 + portable 单 exe；图标 `electron/build/icon.ico` 待生成。
- 文档漂移待修：AGENTS.md / docs/electron-guide.md 仍写 Electron 33 / electron-vite 3 / builder 25，且 guide 里 axios baseURL 方案与实际代码（纯 fetch）不符。

## 打包计划 A/B 评审 + 最终版 C

- 评审结论：**A（HTTP 同源托管）优于 B（app:// 自定义协议）**，以后端进包方案两者一致（pnpm deploy + extraResources + ABI rebuild + pathToFileURL 导入）。
- B 的缺陷：`app://local/session/<id>` 深链刷新时 `base:"./"` 会让 `./assets/*` 解析到 `/session/assets/*` 白屏（B 只兜 HTML 不兜资源）；目标写"离线可用"与 CDN/LLM 事实矛盾；建议删 `@tauri-apps/api` 是误判（pencil 字体/菜单有动态 import）。
- A 的缺陷：dev 分支 `join(__dirname,"../../backend/dist")` 在 out/main 下会指到 electron/backend/dist。
- 最终版交付：`docs/plan-windows-exe-packaging-C.md`，四个核心决策 D1 HTTP 同源托管 / D2 `ELECTRON_BUILD=1 → base:"/"` 开关 / D3 pnpm deploy 自包含 + 路径导入 / D4 硬风险前置（先 deploy+rebuild 出能响应 /health 的包）。
- C 相对 A/B 新增的工程护栏：`backend/package.json` 加 `files:["dist"]` + 产物扫描 fail-fast（防 .env/src 进包）；dev 不内嵌 backend（沿用 :3000 + Vite proxy，免 workspace 依赖）；Express 5 下 SPA fallback 用 `app.use` 而非 `app.get("*")`；electronVersion 从 electron/package.json 读取不硬编码；Host/Origin 白名单防 DNS rebinding；调试用 `electron-builder --dir`，最后才打 NSIS/portable；electron 包名保持 `electron` 不改。

## 方案 C 实施完成（Windows exe 已产出）

- 产物：`electron/release/0.1.0/OpenPRD-Setup-0.1.0.exe`（133,214,812 B）与 `OpenPRD-Portable-0.1.0.exe`（133,004,780 B）。`pnpm dist:win -- --dir` 与正式 `pnpm dist:win` 均验证通过。

- 实施期关键坑（已写进 plan C 附录二 / electron-guide）：
  ① electron-vite 5 + Vite 8 必须显式 `build.target: node22`；TS6 需 `ignoreDeprecations: 6.0`。
  ② **pnpm deploy 在 Windows 是硬链接**，直接 rebuild 会污染主仓库 store；必须隔离副本 + 断开硬链接注入。曾误把主仓库 .node 换成 Electron ABI，用 `prebuild-install --runtime=node --target=22.22.2` 下载 v127 后 rename+copy 恢复。
  ③ Electron 42=ABI 146，`better-sqlite3@12.10.0` 无预编译包且 V8 源码不兼容（C2660）。升级 `^12.11.1` 后改用 `prebuild-install --runtime=electron --target=42.1.0` 直接取 electron-v146 包，不需要 MSVC。全量 `pnpm install` 在本机极慢，最终用「pnpm store add + 从 npmmirror tarball 单独部署 .pnpm 目录 + junction 链接」完成。
  ④ frontend `vue-tsc -b` 有一批既存类型错误 → 新增 `build:desktop`（纯 vite build）供打包用，Web 构建脚本不变。
  ⑤ **electron-builder 的 extraResources 会按目录名排除 node_modules**：先由脚本展平 pnpm 依赖为 `.packaging/runtime`（真实文件），再把 dist/ package.json/ node_modules/ 拆成三条独立映射；Skills 用 filter 排除 skill-custom-*。
  ⑥ `process.execPath` 可能是 `C:\Program Files\nodejs\node.exe`，`spawnSync` 走 shell:true 会被截断成 `C:\Program` → 调用 node 时改 `shell:false`（用户手动跑时暴露）。
  ⑦ 当前 WorkBuddy 会话通过 NODE_OPTIONS 注入删除保护（scope:turn 累计 50 次后拦所有删除），Vite 清空 dist、node-gyp clean、NSIS 清理临时卸载器都被拦；脚本用「旧目录整体改名 + 唯一时间戳名」绕开，正式打包在用户终端或 `NODE_OPTIONS=""` 下无此问题。winCodeSign 缓存在本机因无符号链接权限解压失败，已手工预置 `Cache/winCodeSign/winCodeSign-2.6.0`（排除 darwin 目录）。

## 后续版本更新流程（已写入 docs/electron-guide.md 新章节）

- 核心：改代码 → 提升 `electron/package.json` 的 version → `pnpm dist:win`（可先 `pnpm dist:win -- --dir` 快速验证）。产物版本**只由 electron 包的 version 决定**（`release/${version}`、artifactName）。脚本每次自动重置 .packaging 并重建，不需手动清理。
- 硬规则：不要改 `appId` / `productName`（Windows userData 路径与升级识别依赖它们，改了历史数据会「看不见」）；`deleteAppDataOnUninstall:false` 保证卸载保留数据。
- 变更多余动作：npm 依赖变化先 `pnpm install`；DB schema 变化在 `backend/src/db/migrations.ts` 追加 `if (version < N)` 块并 `db.pragma("user_version = N")`；换图标用 `pnpm icon`；升级 Electron 必须确认 better-sqlite3 有对应 `electron-v<ABI>` 预编译包（否则要 MSVC 源码编译）。
- 目前 `publish: null`，无自动更新；要接 electron-updater 还需代码签名与发布源。

## 扩展 macOS / Linux 三平台打包（2026-11-15）

- **调研结论**：electron-builder 26 官方文档明确 macOS dmg 需要 macOS 主机（hdiutil/签名），Linux 包在 Windows/macOS 上构建可能 hang/失败（建议原生 Linux 或 Docker）。better-sqlite3 12.11.1 的 `electron-v146-{win32-x64,darwin-x64,darwin-arm64,linux-x64,linux-arm64}` 预编译包**全部 HTTP 200**，三平台都无需源码编译。
- **重命名**：`scripts/build-win-exe.mjs` → `scripts/build-desktop.mjs`，参数 `--platform=win32|darwin|linux` / `--arch=x64|arm64`；根命令新增 `dist:mac`、`dist:linux`，`dist:win` 保持兼容。所有引用（AGENTS.md、electron-guide.md、plan C、yml 注释、vite.config.ts 注释、package.json）已同步。
- **脚本泛化**：按目标平台/架构取 `electron-v146-<platform>-<arch>` 包；`packageApp()` 按平台拼 `--win/--mac/--linux` + arch；release 清理识别 `*-unpacked` / `mac*`；`printSummary()` 按平台列产物扩展名（exe / dmg / zip / AppImage / deb）。非 macOS 主机执行 `dist:mac` 直接拒绝并给清晰提示；Windows 上 `dist:linux` 警告但允许尝试。
- **图标**：`generate-icon.py` 由同一 `frontend/public/favicon.svg` 额外产出 `icon.icns`（icp4/icp5/ic07/ic08/ic09 PNG 条目）与 512×512 `icon.png`；浏览器查找扩展到 macOS `/Applications` 与 Linux `/usr/bin`（CI runner 可用）。
- **配置**：`electron-builder.yml` 补全 mac（dmg+zip、icon.icns、`identity: null`、`hardenedRuntime: false`、category）与 linux（AppImage+deb、icon.png、`executableName: openprd`、category）；`electron/package.json` 加 author/description（deb 元数据）。
- **CI**：新增 `.github/workflows/desktop-release.yml`，matrix = windows-latest(x64) / macos-latest(arm64) / ubuntu-latest(x64)，tag `v*` 或手动触发，先 `pnpm icon` 再各平台命令，上传 artifacts。
- **健壮性**：`pnpm deploy` 在 Windows 上偶发因创建 `node_modules/.bin/*.ps1` 报 EPERM → 脚本改为检查产物完整性（`dist/index.js` + `.pnpm` ≥100 包）后容错继续；`prebuild-install` 走 GitHub 偶发代理 502 → 加 3 次重试。
- **验证 / 实测结论**：Windows 回归 `pnpm dist:win` 成功；`pnpm dist:mac` 在 Windows 上按预期给出明确拒绝提示；`pnpm dist:linux` 在 Windows 上参数传递已验证正确（`platform=linux arch=x64`、Linux Electron 与 `electron-v146-linux-x64` 均下载成功），但 AppImage 阶段创建 `usr/share/icons/...` 符号链接需要管理员权限，报 `A required privilege is not held by the client` → **本机 Windows 无法产出可用 Linux 包**，正式产物交给 `ubuntu-latest` runner。
- **关键坑（务必记住）**：`pnpm --filter electron dist -- --linux --x64` 会被 pnpm 吞掉 `--` 后的平台参数，electron-builder 静默按宿主平台产出 Windows 包，且混入 Linux ABI 的 `.node`，脚本一度显示"完成"。已改为 `pnpm --filter electron exec electron-builder --linux --x64`，并加目标平台产物存在性校验。另：yml target 里写死 `arch` 会覆盖 CLI 架构，已全部移除，由 `--x64/--arm64` 决定。
- Windows exe 曾因上述 bug 被打入 Linux ABI 原生模块，最后已重跑 `pnpm dist:win` 覆盖为正确版本；清理规则补上 `__appImage-*` 临时目录。
