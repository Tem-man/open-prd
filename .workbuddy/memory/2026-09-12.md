## 原型编辑器 AI 二次修改触发链路分析

用户询问：原型编辑器中 AI 画好图之后，二次修改的触发链路是什么。通过源码梳理得出完整结论（详见对话回复），要点：

- 入口收敛于 `frontend/src/pencil/components/ChatPanel.vue` 的 `handleSubmit(text)` → `chat.sendMessage({ text })`；另有"重新生成"（PRD 依据）和 "Continue"（50 步上限后）两个按钮入口。
- 会话连续性：`app/ai/chat/transports.ts` 的 `createChatSessionManager` 按 EditorStore（WeakMap）缓存 `UIMessage[]`，二次修改时模型能看到首轮画图产生的 node ID / 名称 / 结构。
- 请求构造：`ensureChat()` → `createToolLoopTransport()`（ToolLoopAgent + DirectChatTransport，Vercel AI SDK v6），instructions = system-prompt.md +（可选）PRD 原型设计依据（`app/ai/prdContext.ts`）。
- 画布桥接：`app/ai/tools/index.ts` 的 `createAITools` → `toolsToAI(CORE_TOOLS, { getFigma: () => makeFigmaFromStore(store) })`；`app/automation/bridge/figma-factory.ts` 每次 execute 时把 `store.state.selectedIds` 注入 `api.currentPage.selection` —— 用户画布选区经 `get_selection` 工具成为二次修改上下文。
- 修改执行：模型在 tool loop（上限 `MAX_AGENT_STEPS = 50`）中调 modify/structure 工具（update_node、set_fill、batch_update、render+replace_id 原子替换等），用 describe 自检。
- 每个 mutating 工具：`onBeforeExecute` 快照 → `onAfterExecute` 加载字体 → `computeAllLayouts`（Yoga）→ `requestRender`（Skia）→ `pushUndoEntry('AI: xxx')` 进撤销栈；`onFlashNodes` 高亮改动的节点。
- 结论：没有独立的"二次修改模式"，二次修改 = 同一 Chat 会话里的新一轮 tool loop，靠历史消息中的 ID 上下文 + FigmaAPI 实时桥接定位目标。与墨刀（后端文件级 Agent + 版本目录）不同，本项目为前端直连 tool loop + 内存会话 + 撤销栈版本化。
